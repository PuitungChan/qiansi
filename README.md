> 一款单机 2D 物理动作游戏。

## 一句话设计

主角是全场最轻的东西（质量 0.5）。丝线连上什么，决定了**是你飞向它，还是它飞向你**。

着地时你是锚点，可以甩动物体；离地时物体是锚点，你被甩飞。
**一个系统同时产出攻击、位移、逃命三种玩法。**

---

## 七条不可动摇的设计决策

1. 丝只能拉，不能推
2. 玩家质量极小，着地 / 离地决定谁是主动方
3. 威力只来自角动量守恒，不来自数值加成
4. 敌人弱点 = 物理量分类（动量 / 动能 / 反向力差）
5. 丝线数量本身就是进度条（1 → 2 → 3 → 4）
6. 固定物理步长，全局确定性
7. 涌现必须被「翻译」给玩家（慢镜 + 命名）

> 任何需求若与这七条冲突，应被拒绝。

## 核心验收标准

| AC | 内容 | 为什么重要 |
|---|---|---|
| **AC-01** | ≥ 60% 首次玩家在 5 分钟遭遇战中 60 秒内自主用石块击杀 | **项目存续的判定点** |
| **AC-05** | 同一回放在 3 台设备 + 服务端产生相同哈希 | 速通/排行榜/回放的前提 |
| AC-22 | L4 视差 = 1.00，正交相机，L5/L6 遮挡 ≤ 15% | 预判线不说谎的前提 |
| AC-44 | 删除整个广告模块后仍能编译并通关 | 广告不长进核心循环 |

## 开发路线

| 里程碑 | 周期 | 内容 | 判定 |
|---|---|---|---|
| **M0 物理原型** | 3 周 | 灰盒房间：方块 + 石块 + 墨甲 | 「我还想再甩一下」 |
| **M1 垂直切片** | 3 个月 | 序章前 12 分钟，全灰盒 | **AC-01 ≥ 60%** |
| **M2 小游戏验证版** | 4 个月 | 3–5 关 + 挑战模式 + 广告接口 | 留存与分享率 |
| **M3 完整版** | 12–18 个月 | 6 章买断版 | 商业表现 |

**M0 与 M1 之间不做任何美术。物理手感不成立的话，水墨再美也没用。**

## 协作方式

- **决策写进 `DECISIONS.md`** —— 跨会话的上下文靠文件，不靠对话
- **需求变更走追踪矩阵** —— 先做影响分析，再改代码
- **每次交付记 `CHANGELOG.md`**
- **真机试玩每周 ≥ 1 小时** —— 这是唯一无法替代的验证手段

详见 `docs/Gitee_协作规范.md`。
