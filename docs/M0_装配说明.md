## 2. 装配场景（4 步，约 1 分钟）

> **我没有交付 `.scene` 文件，这是刻意的决定**，原因见 §7。

### ⚠️ 先知道一件事：新建的 Scene 里**没有 Canvas**

Cocos Creator 里「资源管理器右键 → 新建 → Scene」建出来的是**空场景**，里面一个节点都没有。
带 Canvas 的那套是**新建工程时的默认场景模板**，不是"新建场景"的模板。

而本工程的入口脚本必须挂在 Canvas 上（全部渲染坐标都以**画布中心**为原点）。
所以要多做一步，自己加 Canvas。

### 步骤

1. **建场景**：资源管理器里右键 `assets` → 新建 → 文件夹，命名 `scenes`；
   再右键 `scenes` → 新建 → Scene，命名 `M0Room`，双击打开。
2. **加 Canvas**：在**层级管理器**里右键空白处 → **创建 → UI 组件 → Canvas**
   （有的版本显示为「创建 → UI → Canvas」）。
   Canvas 通常会**自动带一个 `Camera` 子节点**；如果没有，右键 Canvas → 创建 → 摄像机，再加一个。
3. **挂脚本**：选中 `Canvas`，把 `assets/scripts/cocos/Bootstrap.ts` 从资源管理器
   **拖到属性检查器**上（或点属性检查器下方「添加组件」→ 自定义脚本 → QiansiBootstrap）。
4. **保存并播放**：`Ctrl + S`，然后点工具栏的 ▶ **播放**。

装配完成后，层级管理器应该长这样：

```
M0Room (Scene)
└── Canvas              ← Bootstrap.ts 挂在这里
    └── Camera
```

**房间、主角、石块、墨甲、HUD、调试面板全部由 `Bootstrap.ts` 在运行时程序化创建**，
场景里不需要再放任何其他东西。

> **为什么脚本必须挂在 Canvas 上**：`Coordinates.ts` 里所有换算都以画布中心为坐标原点。
> 挂到 Scene 根节点或普通节点上，整个画面会偏出屏幕，而现象是"全黑"——与"脚本没编译好"
> 极难区分。所以 `Bootstrap.start()` 里加了一条检查，挂错位置会在控制台明确报错并告诉你怎么修。

> 为什么要这样设计：Cocos 的 `.scene` 是带 uuid 交叉引用的序列化 JSON，只有编辑器能可靠生成。
> 我把所有内容都放进代码，让 `.scene` 里必须手写的东西降到**一个脚本引用**——
> 这样"场景格式对不对"就不再是交付风险（详见 §7）。

## 3. 操作方式

### 键鼠（设计文档 §3.2 / FR-ACT-005，**v0.3.0 起调整过**，见 D-034）

| 操作 | 按键 |
|---|---|
| 移动 | `A` / `D` |
| **牵** | 按住左键**拖**向目标，**松手**连接；拖向空处取消 |
| **收** | **按住左键不动**（≥180ms）· 滚轮**上** · 按住 `空格` |
| **放** | 滚轮**下** · 按住 `Shift` |
| **断** | **右键** · **`Q`** · 轻点画面上的丝线（<180ms 且没移动） |

> **断丝给了三条路**：实机反馈「点击丝线太需要精细度」，所以右键 / `Q` 是主手段
> （都是"断最近的一根"），点击降级为备选。丝线判定半径也从 22px 加大到 **34px**。
>
> 左键的三种语义用**位移 8px** 与**时间 180ms** 两个阈值分开：
> 拖动了 = 牵；按住不动超过 180ms = 收丝（对应设计 §7 的「按住不放」）；轻点 = 断丝。

### ⚠️ 攻击必须"先松手"（v0.4.0 起，见 D-037）

**被丝牵住的物体不造成伤害。** 这是设计 §2.3 的原文——「**断丝 = 攻击**」。

想打死墨甲，流程必须是：

```
牵住石块 → 甩起来（左右跑动 + 收丝）→ 右键/Q 断丝 → 石块飞出去砸中
```

**把石块收到墨甲身上磨是没用的**（不掉血）。另外还有一个速度门槛：
低于 **6 m/s** 的接触算"蹭到"，也不算伤害（但仍有撞击反馈）。

### ⚠️ 敌人不能牵（v0.4.0 起，见 D-038）

R1 阶段**丝线牵不到敌人身上**。依据设计 §5 心法表：「**墨丝**」是**第四章**才解锁的
「可以附着于无相本体」——在此之前敌人不是可附着目标。所以现在牵着丝去套墨甲是连不上的。

### 触屏（设计文档 §3.1 / FR-ACT-001~004）

| 操作 | 手势 |
|---|---|
| 移动 | 左半屏拖拽（虚拟摇杆） |
| **牵** | 右半屏从主角向外拖拽，松手连接 |
| **收** | 右半屏**按住不放**（≥ 180ms 且未移动） |
| **断** | 点击画面上的丝线（半径 34px） |

> ⚠️ 触屏路径是**粗版**，只做了设计文档写明的那几个手势，没有做左手模式（FR-ACT-008，R3），
> 也**没有**加"下滑/外推放丝"（FR-ACT-003 的已知缺口）。触屏精度是 D-014 明确要求
> "R1 实机验证"的项，请重点看这一条。

### ⚠️ 丝线到顶不会断（v0.3.0 起，见 D-032）

**张力打到 100% 时丝线不会断裂**，而是"拉紧"：轻的一端被拉向重的一端。
具体表现：

- **你站在地上**（等效质量 ∞）⇒ 被牵的物体被拉过来，你几乎不动
- **你在空中**且物体比你重 ⇒ **你被拉过去**
- 两端都动不了 ⇒ 谁也过不去

所以张力条到顶 = "现在是最紧的状态"，**不是危险信号**。不用再猜"什么时候会断"了。
唯一会让丝位消失的是你自己断开它（右键 / `Q` / 点击），断掉后该丝位冷却 1.5 秒。

### 调试热键

| 键 | 作用 |
|---|---|
| `R` | 复位场景（回到初始状态，hash 也回到初值） |
| `P` | 预判线开关 |
| `G` | 调试面板开关 |
| `T` | 慢动作 0.25×（看断丝瞬间的细节） |
| `N` | 丝位数量 1 → 2 → 3 → 4 循环（重建场景） |
| `F1` / `F2` | 播放 / 停止**内置演示脚本** |
| `H` | 把最近 600 帧的输入序列 + 当前 hash 打到控制台 |

> **`H` 是给我用的。** 你试玩时如果觉得"这一下甩得不对"，按 `H`，把控制台里那坨文本发我，
> 我就能在你本机之外**逐帧精确复现**那一刻（NFR-MNT-003 回放导入导出）。

## 7. 为什么没有交付 `.scene` 文件 ★

你在开工前选了「我生成完整工程，场景极简」。我**部分偏离**了这个选择，必须说清楚原因：

Cocos Creator 的 `.scene` 是**带 uuid 交叉引用**的序列化 JSON：组件用**压缩后的 uuid**
作为 `__type__`，节点之间用 `__id__` 索引互指，还有 `cc.SceneGlobals` 等必需子树。
压缩 uuid 的算法、以及不同小版本之间字段的增删，**只有编辑器本身能可靠产出**。

而本机**没有 Cocos Creator**，所以我写出来的 `.scene` **一行都无法验证**。
一个格式不对的场景文件有可能让整个工程**打不开**——那你就被卡在第一步，而且很难自行排查。

权衡之后我选择：**把一切放进代码，让场景里只剩下"一个脚本引用"**。
代价是你多花 30 秒点三下；收益是"场景格式"这个风险被彻底消除。

如果你希望我还是生成一个 `.scene` 试试，**可以**——但请在你**已经装好编辑器**之后
告诉我版本号，我会生成一份并请你在一个**新工程副本**里先试导入（这样即使坏了也
不会影响正常工程）。
