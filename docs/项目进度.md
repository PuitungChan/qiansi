**关键决策与发现**（详见 `DECISIONS.md`）
- **D-021 被实测推翻**：把张力 0–400 当牛顿时，玩家"跑开拉直丝线"2 个 tick 就绷断（480 N），"按住放"收丝峰值 752 N 自断。→ **D-029**：0–400 是**显示刻度**，物理断裂载荷改为 **1200 N**（按"石块 20m/s 在 r=2m 处留 30% 余量"反推）。**这需要改 SRS，待批准。**
- **D-027**：主角与被牵物体不参与碰撞。开启时石块被主角自己的身体卡死，甩动速度上限只有 5.8 m/s；关闭后可达 15–23 m/s。
- **D-028**：k 1600→1000、ζ 0.5→0.2（瞬态峰值张力 `≈ v√(km)`，太大就一拉就断）。
- **D-030**：收丝机在 80% 额定负载处堵转 —— 否则"按住不放"必然自断，与设计 §7 教学节奏冲突。
- **D-031**：**关卡尺度受投掷射程 `v²/g` 约束**。g=20 下石块实测 15–23 m/s ⇒ 射程 11–26m。第一版把墨甲放在 16m 外，演示脚本完全打不中。→ **建议写进 SRS：需要投掷解决的遭遇战，目标距玩家 ≤ 8m。**

**验证了什么**
- `npm test` → 语法检查 27 个 `.ts` 全通过；`core/` 14 个文件零外部依赖；**64 项测试全绿**
- 确定性：900 tick 脚本两次独立运行，状态哈希轨迹**逐位一致**（AC-05 的单机部分）
- 伤害口径：附录 A 每一个算例 + 附录 B 每一个血量 + 设计 §4.1 每组克制关系
- 手感下限：石块能甩到 ≥15 m/s；纯收丝不会自断；内置演示能投中墨甲（摘要哈希 `3c7f7016969b215f`）

## 7. 这个文件怎么维护

**我（AI）每次收工前必须做三件事：**

1. 更新 §0 速览的「当前阶段 / 整体进度 / 上一次做完的事 / 眼下卡在哪 / 最近更新」
2. 更新 §2 里受影响的需求状态 —— **状态变了必须同时给出证据**（哪条测试、哪次试玩、哪个提交）
3. 在 §3 追加一条工作日志，格式固定：
   ```
   ### <日期> · 第 N 轮 — <这件事叫什么>
   **产出**：……
   **关键决策与发现**：……（有决策就写进 DECISIONS.md，这里只写摘要与链接）
   **验证了什么**：……（写命令与结果，不要写"应该没问题"）
   **没验证什么**：……（这一节不许空着——如果没有，说明你没想清楚边界）
   **提交**：……
   ```

**为什么 §3 的「没验证什么」不许空着**：这个项目最大的风险不是"做得慢"，而是"我以为做完了"。
把边界写下来，下一次开工的人（可能还是我，但没有记忆）才知道从哪里接着验。
