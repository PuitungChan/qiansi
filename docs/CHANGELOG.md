## [0.5.0] — 2026-09 — **投掷射程修复 + 文档归位**

### 修复

- **D-039 · 「石头速度衰减太快，基本上要贴近敌人才能砸到」**
  - 实测（石块 20 m/s 平抛）：旧摩擦 0.4 ⇒ 等效 μ=0.566 ⇒ 减速度 **11.3 m/s²**，
    12m 处只剩 11.3 m/s（伤害 11.3），15m 处只剩 7.7（逼近伤害门槛 6）
  - **根因**：M0 没有刚体自转（D-025）⇒ 石块**不能滚，只能滑**，而滑动摩擦远大于滚动摩擦
  - 修法：新增 `PROP_FRICTION = 0.1`（等效摩擦，用低滑动摩擦近似"它会滚"）。
    12m 处 **11.3 → 16.2 m/s**（保留 81%，旧值 57%），有效满伤害射程 **~9m → ~15m**
  - **证据**：内置演示脚本自己变了 —— 修复前需助跑 180 tick（3 秒）才砸得到，
    修复后只需 **30 tick（0.5 秒）**；断丝时机 397 → 121 tick，断丝速度 9.91 → 13.17 m/s
  - 这是 **D-025 的补偿措施**；R2 若引入自转，应改回真实滑动摩擦，让"滚"本身产生低阻力

## [0.4.0] — 2026-09 — **攻击门槛与附着规则**

> 创始人第 2 轮实机反馈。三条里有两条是**我偏离了设计文档**，不是新设计问题。

### 变更（**破坏性：改了战斗规则**）

- **D-037 · 攻击必须"先松手"**
  - **被丝牵住的物体不造成伤害**。设计 §2.3 原文就是「**断丝 = 攻击**」，攻击动作本身
    就是松手——这条规则本来就在文档里，是**我实现时漏掉了**
  - 堵死的退化玩法：把石块收到敌人身上磨、把敌人顶到墙上蹭、用丝把敌人挤死
  - 另加 **`MIN_DAMAGE_SPEED = 6 m/s`**（= 主角走速）：低于它算"蹭到"不算"砸到"。
    与 `MIN_IMPACT_SPEED`（0.5，管接触反馈）分工不同
  - 创始人原话：「只要石头碰到了敌人就会造成伤害……我可以直接把石头拉过去就能击杀敌人，
    这和我原来通过甩过去砸到敌人的初衷不符」
- **D-038 · 敌人不可被丝线附着**
  - 依据设计 §5 心法表：「**墨丝**」（第四章）—— 可以附着于「无相」本体。
    也就是"牵敌人"是**第四章才解锁的能力**，R1 阶段敌人不是可附着目标
  - 此前 `M0Scenario` 里墨甲的 `anchorable` 误设为 `true`，已改为 `false`
  - 这个错误不只是"多一个能力"——它直接跳过了设计留给玩家自己发现的「双截棍」技术空间

### 修复

- **D-036 · 「墨甲和石块卡在一起」**
  - 实测牵着石块把墨甲顶到墙上时，两者稳定互相嵌入 **0.236 m**（石块半径才 0.5）
  - 根因：D-032 的丝线刚性位置约束每 tick 精确钉死绳长，而碰撞分离只修正 25%——
    两条位置约束"各解一次"时刚性那条每次都赢
  - 修法：把「丝线约束 ⇄ 碰撞分离」放进**同一个交替迭代**（4 次），位置修正系数 0.25 → **0.8**
  - 效果：最大穿透 **0.236 → 0.084 m**，稳态 **0.196 → 0.037 m**（约石块半径的 7%）
- `demo.ts` 的"断丝速度"改为在断丝**之后**那一刻测量（此前测的是"丝还在拉"的状态）

### 测试

- 73 项（新增 D-036 / D-037 / D-038 行为 5 项）；演示哈希基线更新为 `17801d9bc8f55fee`

## [0.3.0] — 2026-09 — **依据首轮实机反馈改造机制**

> 创始人第一次真正玩到画面，给出 6 条问题 + 2 条方案。**这是 `core/` 第一次被真人检验。**

### 变更（**破坏性：改了游戏机制**）

- **D-032 · 张力到顶不再断丝，改为「拉紧」**（创始人提案）
  - 取消"超限断弦 + 0.8s 硬直"（原 FR-PHY-006）。张力到达上限后，丝线变成**刚性距离约束**：
    修正量按逆质量分配 ⇒ 主角着地时物体被拉过来、主角离地时自己被拉过去、两端都动不了就谁也过不去
  - 玩家反馈原话：「在实际操作中**丝线什么时候会断太难掌握了**」
  - 副作用（正面）：甩速反而更高，实测 8 种操作模式 **12.3–22.6 m/s**（旧版 12–23），
    且**没有任何一种会断丝**
  - **连带删除收丝机堵转（D-030 作废）**：它的存在理由是"防止弹簧伸长失控把丝绷断"，
    伸长量现在被位置约束直接夹住，前提消失
  - 保留：`stunRemaining` 与"硬直期间不响应输入"的机制（留给受击/坠地等其他硬直来源）
- **D-033 · 脱离豁免**（修复实机反馈 #4「石头把主角也撞了过去」）
  - 实测：摆动中石块到主角中心最近 **0.129 m**，而主角半宽 0.4 / 半高 0.8 ⇒
    **断丝那一刻石块在主角身体内部**，豁免一撤销就被求解器猛推出去
  - 规则：「已经在你身体里的东西，不该再"撞"你一次」；两者分开后自动恢复碰撞
- **D-034 · 输入方案调整**（创始人提案，实机反馈 #3）
  - 新增 **右键 = 断最近一根**、**`Q` = 断最近一根**（`Q` 此前根本没实现，是 FR-ACT-005 的缺口）
  - **按住左键不动（≥180ms）= 收丝**，终于对得上设计 §7 的「按住不放」
  - 丝线线宽 1.5–5px → **4–11px**，两端加端点圆；断丝判定半径 22px → **34px**
  - 保留"轻点丝线即断开"（FR-ACT-004），但降级为备选手段

### 修复

- **反馈 #1「按住左键瞄准时人物自己滑了」—— 真 bug，已修**
  - 根因：左半屏触屏摇杆的 `touch.down` **会卡死**（`onTouchEnd` 原先按"抬起点在哪半屏"
    分支，手指从左半屏划到右半屏再抬起时走的是另一条分支，状态永远清不掉），
    于是 `sample()` 每 tick 都按摇杆偏移算 `moveX`；叠加鼠标与触摸可能同时派发，
    就变成"拖拽瞄准的同时在推摇杆"
  - 修法：**指针来源仲裁**（谁先按下谁独占，另一来源在本次按下期间全部忽略）
    + **用触摸 id 跟踪两根手指**（不再靠"当前坐标在哪半屏"判断归属）
- **D-035 · 主角与 prop 类物体一律不碰撞**（创始人确认，反馈 #6）
  - 实测主角其实**没被挡住**（3 秒走 17.69m / 理论 18.00m），是石块被推着走、
    始终停在前面 0.89m，**观感**像堵着
  - 现在主角可以走过去；`prop` 成为唯一豁免依据，**取代 D-027**，
    并让 D-033 的"脱离豁免"只在敌人身上才需要
- 调试面板底衬画错位置（`Graphics.rect` 的坐标是左下角，而屏幕左上角是 `(-960, +540)`）
- 新增 `assertUnderCanvas()`：脚本挂错节点时明确报错，而不是让用户对着黑屏猜
- `Bootstrap.start()` 打印启动日志，用于区分"脚本没跑起来"与"画不出来"

  - D-031 关卡尺度受投掷射程 `v²/g` 约束（→ 建议写进 SRS 的关卡设计约束）
