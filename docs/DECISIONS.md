# 决策记录（DECISIONS）

> **这个文件是这个项目的长期记忆。**
>
> 跨会话的上下文只能靠文件承载。任何重要决定——尤其是「为什么不做某事」——都必须写在这里，
> 否则下次开工时没人（包括 AI）知道。

---

## 使用规则

1. **每个决策一个编号**，格式 `D-XXX`
2. **必须写「理由」和「影响面」**，只写结论等于没写
3. **不删除已废弃的决策**，改状态为「已废弃」并写明被谁取代
4. **状态变更要记日期**

状态：`已决` / `待决` / `已废弃` / `待验证`

### D-017 · 物理内核自研，Cocos 只负责渲染与输入 ★

| 项 | 内容 |
|---|---|
| **状态** | 已决（**待创始人追认**，见文末变更日志） |
| **日期** | 2026-09 |
| **决策** | 刚体求解、丝线、伤害、确定性步进全部由**零引擎依赖的纯 TypeScript 内核**实现；Cocos Creator 只承担渲染、输入采集、资源与打包 |
| **理由** | 三条硬理由：① **AC-05（确定性）是 R1 的两条存续判定点之一**，而 Cocos 内置 Box2D 的固定步长由 `PhysicsSystem2D` 累加器驱动，我在没有编辑器的情况下**无法验证**它跨设备是否逐位一致；自研内核可以在本机用 Node 跑确定性回归，把 AC-05 从"希望"变成"证据"。② 本机没有 Cocos Creator，若物理逻辑依赖 `cc`，则**整条 M0 交付物一行都验证不了**。③ 内核与引擎解耦后，万一引擎路线变更，迁移成本只剩渲染层 |
| **影响面** | 与 SRS §2.3「物理：Box2D（刚体）+ 自研 Verlet（绳索）」**存在偏差**，须走 RTM 影响分析后更新 SRS；NFR-MNT-004（单元测试）变得可行且成为交付物 |
| **代价** | 自研求解器只覆盖 M0/R1 需要的形状与约束（圆 + 轴对齐盒、无自转、顺序冲量求解）。柱体滚转、关节、缠绕等后续需求可能需要重新引入 Box2D，届时通过 `PhysicsBackend` 接口替换 |
| **回退方案** | 若创始人否决：改为直接调用 Cocos `PhysicsSystem2D`，代价是**放弃本机验证能力与确定性自证**，M0 只能由真机试玩来发现问题 |

### D-020 · 主角移动与丝线连接语义

| 项 | 内容 |
|---|---|
| **状态** | 已决 |
| **决策** | ① 主角**移动**由输入直接驱动目标速度（着地 6 m/s，离地 1.5 m/s 空气控制），通过有上限的加速度逼近，不使用力；② **连接瞬间丝长 = 当时两点距离**（不产生任何拉力），只有玩家主动收丝才产生张力；③ 收/放丝改变的是"目标丝长"，速率 8 m/s（素丝）/ 14 m/s（疾丝），范围 0.5–12 m |
| **理由** | ①"角色控制器 + 目标速度"是 2D 平台游戏的标准做法，手感可预期且与质量解耦；② 若连接瞬间固定 6m，则石头摆放在 6m 内时丝是松弛的，玩家第一次连上会觉得"没反应"，而设计 §7 明确要求"连上后石头微微晃动"；③ 满足铁律 1（松弛不传力） |
| **影响面** | FR-PHY-002/011 / FR-ACT-001~005 / AC-19；M0 房间的物件摆位 |

### D-021 · 张力模型（**已被 D-028 / D-029 修订**）

| 项 | 内容 |
|---|---|
| **状态** | **已废弃**（模型保留，常数被 D-028 / D-029 取代） |
| **日期** | 2026-09（初版）→ 2026-09（实测后废弃常数部分） |
| **初版决策** | 张力是有量纲的力：`T = k·ΔL + c·Δv_axial`（`ΔL ≤ 0` 时 `T = 0`，对应"松弛不传力"）。初版取 `k = 1600 N/m`、`ζ = 0.5`、`T_max = 400 N`（素丝）/ `700 N`（韧丝） |
| **初版的漂亮推论（后被实测推翻）** | `T_max = 400 N` 恰好等于**墨甲（质量 20）的重力** `20 × 20 = 400 N`。素丝吊不起墨甲、韧丝可以——这解释了为什么墨甲的弱点是"动量 mv"而不是"被拉住"。当时把这当作"400 就是牛顿"的直接证据 |
| **为什么被推翻** | 把 400 N 当作真实断裂载荷后，实测定标发现：**玩家只是按住收丝、或向左跑开把丝拉直，张力就会瞬间冲到 750+ / 480 N**，丝在 2–90 个 tick 内自己绷断。连"移动"和"牵着石头走"这种最基础的操作都会断丝，游戏无法进行。证据与重新定标过程见 **D-028（刚度与阻尼）** 与 **D-029（显示刻度 vs 物理载荷）** |
| **保留下来的部分** | ① 张力是弹簧-阻尼模型、单位是牛顿；② **松弛（ΔL ≤ 0）时张力恒为 0** —— 这是铁律 1「丝只能拉不能推」在代码里的唯一落点，被 `tests/rope.test.ts` 锁死；③ 张力分档（60% / 85% / 95%）按**占额定值的比例**计算，因此与常数怎么标定无关 |
| **教训（写给未来的自己）** | "数值上的巧合"不是"设计意图的证据"。一个漂亮的等式（400 = 墨甲自重）值得记下来当假设，但不能拿它替代实测定标——幸好这一点在 M0 阶段就被发现，而不是在 M1 的真机试玩里 |

### D-022 · 伤害结算：按目标弱点择一，不叠加

| 项 | 内容 |
|---|---|
| **状态** | 已决 |
| **决策** | 一次撞击**只结算一条伤害公式**，选取目标弱点对应的那一条：`any`（墨卒）取两者较高值、`impact`（墨甲）只结算冲击、`cut`（墨刃）只结算切割、`tear`（墨缚）/`structure`（墨巢）走各自的专用规则 |
| **理由** | 若两条公式相加，附录 A/B 立刻自相矛盾：石块(4)@25m/s 打墨甲 = 冲击 25 + 切割 10.4 = 35.4 ≥ 30 HP，**一次就死**，而附录 B 明确写"墨甲需要两次石块投掷"。择一后单次冲击 = 4×25/4 = 25 < 30，两次击杀成立，与附录 B 完全自洽 |
| **影响面** | FR-CBT-002/003 / AC-02 |
| **回归护栏** | `tests/damage.test.ts` 用附录 A / 附录 B / 设计 §4.1 的**每一个参考算例**做断言，其中一条专门断言"若叠加就会破坏附录 B" |

### D-023 · 附录 A/B 数值口径复核结论

| 项 | 内容 |
|---|---|
| **状态** | **待创始人拍板** |
| **发现** | 附录 A 的算例 `石块(4) @ 20m/s → 冲击 20` 与公式 `min(4,20)×20/4 = 20` 一致；但附录 B 写"墨甲 HP 30，需要两次石块投掷"，两次冲击 = 40 ≥ 30 成立，**单次 20 < 30 不致死**，口径自洽。真正需要澄清的是**速度口径**：`v_rel` 是撞击瞬间的相对速度，而玩家能甩出的速度上限受张力模型（D-021）约束——`r=6m` 时理论峰值约 `v=24.5 m/s`（`T=400N` 的离心力上限），对应冲击 24.5，仍是两次 |
| **结论** | 附录 A/B **无需修改**。M0 将"石块@20m/s 打墨甲造成 20 伤害、两次击杀"写入自动化测试作为回归基线 |
| **待确认点** | 敌人是否受击后有硬直/位移（文档未写）。M0 暂定：受击仅扣血 + 轻微击退（与来袭动量成正比），无硬直 |

### D-024 · 预判线 = "假设此刻断丝"的重力弹道

| 项 | 内容 |
|---|---|
| **状态** | 已决 |
| **决策** | 预判线用**与主循环完全相同的积分器**前向模拟 18 步（0.3s），初始条件 = 被牵物体当前的位置与速度，**只含重力、不含丝线约束、不含碰撞**，采样成点列后以金色点线绘制 |

### D-025 · M0 刚体不做自转

| 项 | 内容 |
|---|---|
| **状态** | 已决（M0 范围内） |
| **决策** | M0 的所有刚体（主角/石块/墨甲/地形）**没有角速度与转动惯量**，形状只用**圆**与**轴对齐矩形** |
| **理由** | 核心机制（角动量守恒）发生在"物体绕主角旋转"的**轨道**层面，而不是刚体自转；M0 验证的是"甩动爽不爽"，自转只增加求解器复杂度与不确定性。取消自转后确定性更容易证明，且可本地回归 |
| **影响面** | 石块不会"滚动"，在地面上是滑动；灰盒阶段可接受。若真机试玩觉得"石头滚起来才有分量"，R2 再引入自转（已列入风险） |

### D-027 · 主角与被自己牵住的物体不参与碰撞

| 项 | 内容 |
|---|---|
| **状态** | **已被 D-035 取代**（豁免范围从"被牵住的那一具"扩大到"全部 prop"） |
| **决策** | `WorldConfig.collideWithHeld = false`（默认）：主角与**当前被丝牵住的那具刚体**之间不做碰撞检测。断丝/重凝后立刻恢复碰撞 |
| **为什么** | 这是纯玩法取舍，有实测数据支撑：开启碰撞时，石块一被收近就顶在主角自己的盒体上（主角右边缘 4.40m，石块半径 0.5m ⇒ 石块卡在 x≈4.90m），**再也抬不起来**，甩动速度上限只有 **5.8 m/s**；而设计 §7 明确要求"石头被拉向主角……悬在半空，开始摆动"。关掉之后石块可以被收到手部附近并绕主角旋转，石块速度实测可达 **15–23 m/s**，`v ∝ 1/r` 的角动量加速才真正成立 |
| **代价** | ① 被牵住的物体会穿过主角的身体（视觉上要在 R2 用墨色遮挡或"手部抓握"表现掩盖）；② 主角不能站在自己正牵着的物体上 |
| **替代方案** | 若试玩后觉得"穿过身体"很出戏，可改为**缩小主角碰撞体到躯干**（0.4×0.6）并把出丝点抬到头顶，让石块能从头顶过去——但那会牺牲"石块贴着主角身侧"的其余手感 |
| **影响面** | M0 手感的核心前提之一；R2 若引入自转/更复杂形状需重新评估 |

### D-028 · 丝线刚度与阻尼的定标（修正 D-021）

| 项 | 内容 |
|---|---|
| **状态** | 已决（**数值待真机调参**） |
| **决策** | `k = 1000 N/m`、阻尼比 `ζ = 0.2` |
| **为什么 ζ 必须小** | 弹簧-阻尼绳在**突然绷紧**时的峰值张力约为 `v·√(k·m)`，阻尼项在绷紧瞬间再叠加 `2ζ√(k·m)·v`。初版取 `ζ = 0.5` 时，玩家只是"跑开把丝拉直"就会产生 ~480 N 的瞬时张力——实测 383–397 N，**足以绷断**。降到 0.2 后同样动作峰值约 356 N，留出余量 |

| **为什么不取更小** | 真实滚动摩擦在 0.01–0.05 量级，但视觉与手感上太"冰"（石块要滑 50m 才停）。0.1 是折中：12m 处保留 **81%** 速度（旧值 57%），有效满伤害射程 **~9m → ~15m**，石块仍在 3 秒左右自然停下 |
| **最强的证据** | **内置演示脚本自己变了**：修复前需要助跑 180 tick（3 秒）才能砸到墨甲，修复后只需 **30 tick（0.5 秒）**；断丝时机从第 397 tick 提前到第 **121** tick |
| **与 D-025 的关系** | 这是 **D-025 的补偿措施**。R2 若引入刚体自转，`PROP_FRICTION` 应改回真实滑动摩擦值，让"滚"本身产生低阻力——那才是物理上正确的做法 |
| **影响面** | FR-CBT-002 / AC-02；`physics.test.ts` 新增"投掷射程回归护栏"（12m 处必须 > 15 m/s）；**建议给 SRS 补一条关卡约束："投掷有效射程 ≥ 12m"**，与 D-031 的"交战距离 ≤ 8m"一起把关卡尺度夹住 |
