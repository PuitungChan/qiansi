## 1. 引言

### 1.1 目的

本文档将《牵丝》的游戏设计转化为**可验证、可追踪、可验收**的工程需求。它面向程序、美术、QA、发行与合规，作为开发计划、测试用例与验收的依据。

### 1.2 范围

**产品**：单机 2D 物理动作游戏《牵丝》。
**核心主张**：没有连招表，只有物理定律。玩家不产生力量，只重新分配力量。

**包含**：
- 6 章主线（约 28–30 关），单机叙事
- 挑战模式 / 速通模式（异步排行榜）
- 无相墨体（Ink）视觉系统
- 微信小游戏 + PC/移动端买断双形态

**不包含**（明确排除，见 §6.15）：
- 实时多人对战、合作
- 抽卡、体力、广告变现
- UGC 关卡编辑器（列为 v2 候选）

### 1.3 术语与缩写

| 术语 | 定义 |
|---|---|
| **丝 / 灵丝** | 玩家唯一的武器与工具。只能拉、不能推 |
| **牵 / 收 / 断** | 三个核心动词：连接锚点 / 缩短丝线 / 切断释放 |
| **张力（Tension）** | 单根丝线的负荷值，0–400，超限即断 |
| **墨蚀** | 画面边缘向内侵蚀的受伤表现，替代血条 |
| **无相（Ink）** | 敌方种族，浓墨色流体形态 |
| **心法** | 成长系统单位，每种心法增加一种**动词**而非数值 |
| **凝神** | 子弹时间，时间流速 15%，上限 3s |
| **命名** | 高价值物理事件的慢镜 + 毛笔字播报 |
| **玩法层 L4** | 承载物理模拟的 2D 平面，视差速率恒为 1.00 |
| **确定性** | 同一输入序列在任何设备上产生相同物理结果 |
| **IAP** | 应用内购买 |
| **IAA** | 广告变现（本产品**不采用**） |

### 1.4 需求编号规则

```
<类型>-<模块>-<三位序号>
类型：FR 功能 / NFR 非功能 / CR 合规 / DR 数据 / IR 接口
模块：PHY 物理 · ACT 操作 · CBT 战斗 · PRG 成长 · LVL 关卡
      UI 界面 · NAM 命名成就 · SAV 存档 · CHL 挑战速通
      SOC 社交 · IAP 商业化 · OPT 设置辅助 · MTA 叙事
      LIV 运营 · MP 多人
示例：FR-PHY-004
```

## 2. 总体描述

### 2.1 产品定位

| 项 | 内容 |
|---|---|
| 品类 | 2D 物理动作 / 解谜战斗 |
| 目标用户 | 16–35 岁，喜欢《World of Goo》《只狼》《王国之泪》类"理解型"玩法 |
| 单局时长 | 主线单关 3–8 分钟；挑战模式 1–3 分钟 |
| 总时长 | 主线 8–12 小时 |
| 商业模式 | 免费前三章 + 付费解锁后三章（小游戏）；买断（PC/TapTap） |
| 平台 | 微信小游戏、PC(Steam)、移动端买断 |

### 2.2 关键设计约束（做需求判断时的依据）

这七条来自【设计】§1，是需求裁剪的最高依据。任何需求若与之冲突，应被拒绝。

1. 丝只能拉，不能推
2. 玩家质量极小，着地/离地决定谁是主动方
3. 威力只来自角动量守恒，不来自数值加成
4. 敌人弱点 = 物理量分类
5. 丝线数量本身就是进度条（1→2→3→4）
6. 固定物理步长，全局确定性
7. 涌现必须被"翻译"给玩家（慢镜 + 命名）

### 2.3 运行环境

| 项 | 要求 |
|---|---|
| 引擎 | Cocos Creator 3.x（2D 物理 + 3D 相机与视差） |
| 物理 | Box2D（刚体）+ 自研 Verlet（绳索） |
| 小游戏平台 | 微信基础库 ≥ 2.20.0 |
| PC 平台 | Windows 10+ |
| 移动买断 | Android 8.0+ / iOS 12+ |

### 2.4 假设与依赖

| ID | 假设 | 风险 |
|---|---|---|
| A-01 | M1 真人测试证明"玩家会自己想到用石头" | **最高**，不成立则整个设计需重做 |
| A-02 | 2D 绳约束在目标机型上稳定不抖 | 中，Verlet 方案已验证 |
| A-03 | 企业主体可在 R3 前取得版号 | 高，周期 3–6 个月，补正可至 1 年 |
| A-04 | 小游戏 iOS IAP 已打通（2026 年已开放，抽成 15%） | 低 |

## 3. 干系人与角色

### 3.1 干系人

| 干系人 | 关注点 | 主要需求模块 |
|---|---|---|
| 玩家 | 手感、可学性、物理可读性 | FR-PHY / FR-ACT / FR-CBT |
| 家长 | 防沉迷、消费限额 | CR-ANT / CR-PRI |
| 开发者 | 可维护性、确定性、调试能力 | NFR-MNT / FR-PHY-008 |
| QA | 可测性、确定性回放 | FR-PHY-008 / DR-003 |
| 发行 | 买量素材、留存、转化 | FR-CHL / FR-SOC / FR-IAP |
| 平台（微信） | 合规、内容安全、性能分 | CR-* / NFR-PERF |
| 监管 | 版号、实名、内容 | CR-LIC / CR-CNT |

### 3.2 用户角色

| 角色 | 画像 | 关键诉求 |
|---|---|---|
| **新手** | 首次接触，前 5 分钟 | 不需要教程就能自己悟出玩法 |
| **熟练玩家** | 已通关序章 | 稳定的物理手感，可规划的操作 |
| **硬核玩家** | 追求最优解 | 挑战模式、速通、可复现 |
| **速通玩家** | 极限时间 | 确定性、录像、无随机 |
| **回流玩家** | 流失后回来 | 存档不丢、进度可续 |
| **访客** | 未实名/未成年 | 可试玩，受时长与消费限制 |

## 4. 用户故事

**US-01**（新手）
作为**第一次打开游戏的玩家**，我希望**在没有任何文字教程的情况下，靠物理直觉自己发现"我可以用石头砸它"**，以便**在 5 分钟内理解这个游戏允许我自己想**。
- 验收：AC-01

**US-02**（熟练玩家）
作为**已经理解基本操作的玩家**，我希望**在甩动石块时能看到一条预测轨迹和伤害预估值**，以便**验证我对"动量"和"速度"的理解是否正确**。
- 验收：AC-02

**US-03**（熟练玩家）
作为**面对重甲敌人的玩家**，我希望**看到敌人的形状就能知道该用什么弹药**，以便**不必背攻略**。
- 验收：AC-03

**US-04**（硬核玩家）
作为**追求最优解的玩家**，我希望**同一关能用完全不同的方式通关**，以便**反复挑战时仍有新鲜感**。
- 验收：AC-04

**US-05**（速通玩家）
作为**速通玩家**，我希望**同样的操作永远产生同样的结果，并且能回放**，以便**我的成绩是可验证的**。
- 验收：AC-05

**US-06**（硬核玩家）
作为**打出精彩操作的玩家**，我希望**游戏告诉我刚才那一下很了不起，并给它一个名字**，以便**我知道那不是运气**。
- 验收：AC-06

**US-07**（新手）
作为**刚上手的玩家**，我希望**拉紧丝线时能从声音听出离断弦还有多远**，以便**不用盯着 UI**。
- 验收：AC-07

**US-08**（熟练玩家）
作为**触屏玩家**，我希望**只用两根手指就能完成全部操作**，以便**在手机上也能精确操作**。
- 验收：AC-08

**US-09**（硬核玩家）
作为**面对 BOSS 挥砍的玩家**，我希望**能把敌人的力量变成我的力量**，以便**体验"四两拨千斤"**。
- 验收：AC-09

**US-10**（回流玩家）
作为**换设备的玩家**，我希望**进度自动同步**，以便**不用重玩**。
- 验收：AC-10

**US-11**（访客）
作为**未实名的玩家**，我希望**仍能试玩一部分内容**，以便**先体验再决定是否实名**。
- 验收：AC-11

**US-12**（家长）
作为**家长**，我希望**孩子的游戏时长和消费被系统强制限制**，以便**我不必时刻盯着**。
- 验收：AC-12

**US-13**（玩家）
作为**想分享的玩家**，我希望**把一次精彩击杀分享给朋友**，以便**炫耀并邀请他们玩**。
- 验收：AC-13

**US-14**（玩家）
作为**行动不便或色觉障碍的玩家**，我希望**信息不只依赖颜色，并且有辅助模式**，以便**我也能通关**。
- 验收：AC-14

**US-15**（玩家）
作为**完成主线的玩家**，我希望**有可重复游玩的挑战内容**，以便**继续投入时间**。
- 验收：AC-15

**US-16**（玩家）
作为**中式水墨美学的爱好者**，我希望**画面像一幅会动的卷轴**，以便**获得独特的东方审美体验**。
- 验收：AC-16

**US-17**（开发者）
作为**开发与 QA**，我们希望**所有物理事件可记录、可回放、可比较**，以便**定位 bug 与验证确定性**。
- 验收：AC-17

**US-18**（玩家）
作为**付费玩家**，我希望**一次买断章节，没有广告、没有体力、没有抽卡**，以便**尊重我的时间与钱包**。
- 验收：AC-18

## 5. 用例

### UC-01 首次遭遇战（新手核心验证点）★

| 项 | 内容 |
|---|---|
| **参与者** | 新手玩家 |
| **前置条件** | 已完成"牵/收/断"三个动作的引导（序章 0:00–3:00） |
| **触发** | 玩家进入序章第 4 段场景 |

**主流程**
1. 场景右侧出现一只墨卒，缓慢逼近。
2. 场景左侧放置一块石块。**系统不显示任何提示。**
3. 玩家自行连接石块 → 收丝 → 断开。
4. 石块沿物理轨迹飞出并命中墨卒。
5. 系统播放「一石」命名，慢镜 0.3s。

**备选流程**
- 3a. 玩家尝试直接连接墨卒（丝线滑脱，无法附着）。→ 回到 3。
- 3b. 玩家用丝线把自己拉向墨卒（位移），未造成伤害。→ 回到 3。

**异常流程**
- 3c. 60 秒内玩家无有效操作 → 石块发出极克制的微光提示，**不弹文字**。→ 回到 3。

**后置条件**：玩家理解"连接→加速→释放"是攻击手段。

**验收**：AC-01

### UC-02 人型弹弓（三丝组合技）

| 项 | 内容 |
|---|---|
| **参与者** | 熟练玩家 |
| **前置条件** | 已解锁第三根丝（第三章） |
| **触发** | 场景中存在两根立柱与一枚弹丸 |

**主流程**
1. 用第一、二根丝分别连接左右两根立柱（构成弓架）。
2. 用第三根丝连接弹丸（构成弓弦）。
3. 玩家向后退，身体充当第三锚点，将弹丸拉到位。
4. 张力随拉距上升，音高上升、丝线转亮。
5. 断开弓弦丝 → 弹丸以 `v = f(拉距)` 射出。
6. 弹丸命中高速型敌人（墨刃）造成切割伤害。

**备选流程**
- 1a. 只用两根丝（一柱一弹丸）→ 弹丸初速降低约 40%，仍可命中但需更近距离。
- 5a. 拉距不足 5m → 不触发「弹弓」命名。

**异常流程**
- 4a. 张力超过上限 → 丝线断裂，主角硬直 0.8s，弹丸坠落。

**后置条件**：玩家掌握"多锚点蓄能"原理。

**验收**：AC-04

### UC-03 借力打力（终章 BOSS）

| 项 | 内容 |
|---|---|
| **参与者** | 硬核玩家 |
| **前置条件** | 已进入终章第一阶段；已解锁凝神 |
| **触发** | BOSS 挥出巨型墨刃 |

**主流程**
1. BOSS 起手，墨刃以速度 V 挥向玩家。
2. 玩家激活凝神（时间流速 15%）。
3. 玩家用丝连接墨刃**运动方向前方**。
4. 玩家收丝，速度矢量叠加：`v_player = V + v_reel`。
5. 玩家被甩向 BOSS 核心，造成伤害。
6. 凝神结束，时间恢复正常。

**备选流程**
- 3a. 玩家连接墨刃后方 → 被反向拖拽，受到伤害。
- 5a. 玩家在飞行中再次连丝 → 可连续借力（高阶技巧）。

**异常流程**
- 2a. 凝神能量耗尽 → 无法激活，玩家必须闪避。

**后置条件**：BOSS 进入第二阶段。

**验收**：AC-09

### UC-04 挑战模式成绩上传

| 项 | 内容 |
|---|---|
| **参与者** | 硬核玩家 |
| **前置条件** | 主线至少通关一章；已登录微信 |
| **触发** | 玩家进入「墨渊试炼」并完成一局 |

**主流程**
1. 系统以固定步长模拟本局，生成操作记录与校验和。
2. 结算界面显示用时、用丝数、命名数。
3. 玩家点击"上传成绩"。
4. 客户端提交至服务器；服务器**用同一确定性内核重放**校验。
5. 校验通过 → 写入排行榜；不通过 → 拒绝并标记异常。

**异常流程**
- 4a. 服务器重放结果与客户端不一致 → 判定为不同版本，提示升级。
- 4b. 网络失败 → 成绩存本地队列，联网后重传。

**后置条件**：排行榜更新。

**验收**：AC-05

### UC-05 购买并恢复章节

| 项 | 内容 |
|---|---|
| **参与者** | 玩家 |
| **前置条件** | 已实名；已通关第二章最后一关 |
| **触发** | 玩家点击被锁定的第三章入口 |

**主流程**
1. 显示章节包内容与价格，**不显示倒计时、不显示限时折扣**。
2. 玩家确认 → 调起平台支付。
3. 支付成功 → 服务端回调 → 解锁章节。
4. 客户端刷新，第三章可进入。

**异常流程**
- 3a. 支付成功但回调延迟 → 客户端重试查询，最长 30s，期间显示"正在确认"。
- 3b. 用户取消 → 无任何副作用。
- 3c. 换设备 → 提供"恢复购买"入口，凭平台订单恢复。

**后置条件**：章节永久解锁。

**验收**：AC-18

### UC-06 首次启动与实名认证

| 项 | 内容 |
|---|---|
| **参与者** | 新用户 |
| **前置条件** | 首次启动；中国大陆区 |

**主流程**
1. 显示适龄提示（8+）。
2. 展示隐私政策摘要，提供完整版链接，**用户主动同意后才继续**。
3. 调起实名认证。
4. 认证通过 → 判断成年状态 → 进入游戏。

**备选流程**
- 3a. 用户拒绝实名 → 进入**访客模式**：可玩序章前 3 关，不可支付、不计排行榜、单次时长 60 分钟。
- 4a. 判定为未成年人 → 应用防沉迷策略（§8.3）。

**后置条件**：账号状态写入本地与服务端。

**验收**：AC-11 / AC-12

### UC-07 分享击杀战报

| 项 | 内容 |
|---|---|
| **参与者** | 玩家 |
| **前置条件** | 刚刚完成一次带命名的击杀 |
| **触发** | 玩家点击结算界面的"分享" |

**主流程**
1. 系统导出该次击杀的**确定性回放数据**（非视频，体积 < 8KB）。
2. 生成一张水墨风分享图（含命名、伤害、章节）。
3. 调起微信转发。
4. 好友点击后进入小游戏并**直接播放该回放**。

**异常流程**
- 1a. 回放数据包含不支持的版本 → 降级为静态分享图。

**后置条件**：分享链接生成。

**验收**：AC-13

### UC-08 崩溃后恢复进度

| 项 | 内容 |
|---|---|
| **参与者** | 玩家 |
| **前置条件** | 游戏进行中发生崩溃/断电 |
| **触发** | 玩家重新启动游戏 |

**主流程**
1. 读取最近一次**关卡检查点**存档（每关进入时、每次心法解锁时写入）。
2. 恢复到该检查点所在关卡的开头。
3. 显示"已恢复进度"。

**后置条件**：玩家不丢失已完成的关卡进度。

**验收**：AC-10

### 6.1 物理与丝线核心（FR-PHY）

| ID | 需求 | 优先级 | 发布 | AC |
|---|---|---|---|---|

#### 广告位白名单与黑名单（施工依据）

| 广告位 | 判定 | 理由 |
|---|---|---|
| 开局插屏 | ❌ 禁止 | 破坏第一印象；小游戏用户对开局广告容忍度极低 |
| 常驻 Banner | ❌ 禁止 | 直接违反 FR-RND-006（除灵丝外饱和度 ≤ 15%）与留白主张 |
| 死亡后强制激励视频 | ❌ 禁止 | 摧毁「卡关 → 自己想」的学习循环，与 AC-01 直接冲突 |
| 物理 / 战斗数值加成 | ❌ 禁止 | 违反 FR-IAP-006 与 FR-CHL-006 |
| 章节结算插屏 | ⚠️ 限量 | 唯一可接受的插屏位置；频控 ≤ 1 次 / 15 分钟 |
| 外观解锁（激励视频） | ✅ 允许 | 玩家主动触发，不影响任何玩法 |
| 回放导出（激励视频） | ✅ 允许 | 主动触发，且分享本身是增长行为 |
| 挑战模式额外次数（激励视频） | ✅ 允许 | 主动触发，且不进入排行榜成绩的公平性比较 |
| 关卡提示（激励视频） | ⚠️ 慎重 | 变现效率最高，但与本作设计主张直接冲突。仅在序章 / 第一章之后、二次确认之后开放 |
