# 《牵丝》游戏设计方案 v1.0

> 核心主张：**没有连招表，只有物理定律。**
> 玩家不产生力量，玩家只重新分配力量。

---

## 0. 一句话

你是全场最轻的东西。丝线连上什么，决定了是你飞向它，还是它飞向你。

---

## 1. 七条不可动摇的设计决策

这七条是后续一切设计的依据。任何与它们冲突的点子都应该被砍掉。

| # | 决策 | 为什么 |
|---|---|---|
| 1 | **丝只能拉，不能推** | 真实绳子的唯一特性。它让整个系统可预测、可学习，也是"柔弱"的物理基础 |
| 2 | **玩家质量极小（0.5 单位），着地/离地决定谁是主动方** | 一个系统同时产出攻击、位移、逃脱三种用途 |
| 3 | **威力只来自角动量守恒（收丝加速），不来自任何数值加成** | 物理本身就是成长曲线，不需要等级和装备 |
| 4 | **敌人弱点 = 物理量分类（动量 / 速度 / 反向力差）** | 物理即克制关系。玩家看到形状就知道该用什么，可读性由此成立 |
| 5 | **丝线数量本身就是进度条（1→2→3→4）** | 难度曲线 = 动词数量曲线，不需要额外的成长系统 |
| 6 | **固定物理步长，全局确定性** | 速通模式、挑战模式、录像分享的前提。没有确定性就没有可比性 |
| 7 | **涌现必须被"翻译"给玩家（慢镜 + 命名）** | 玩家看不懂的涌现等于不存在。这是把深度变成体验的唯一手段 |

## 2. 物理系统

### 2.1 三条铁律

1. **丝只能拉，不能推。** 松弛状态的丝不传递任何力。
2. **收丝缩短长度，放丝增加长度。** 长度变化是唯一的能量输入，且收丝速度有上限。
3. **角动量守恒。** 收丝时旋转半径减小，切向速度按 `v ∝ 1/r` 增大。

**全部技巧都是这三条的推论。** 玩家只要能推理出"收丝半径变小速度变大"，就能自己发明弹弓、流星锤、连锁撞击。这是"物理引擎当设计师"能真正成立的前提——**设计师不发明技巧，设计师发明让玩家能推理出技巧的规则**。

### 2.2 玩家状态机

```
着地（脚踩实体）
  → 等效质量 = ∞（地面反作用力）
  → 拉丝时：物体被拉向你 → 你能甩物体

离地（悬空 / 被拉起）
  → 等效质量 = 0.5
  → 拉丝时：你被物体拉过去 → 物体能甩你
```

这条规则**必须在第一关就教给玩家**，因为它解释了这个游戏的一切。

### 2.3 丝线的两种松手方式

| 动作 | 效果 | 代价 |
|---|---|---|
| **放丝** | 长度增加，张力下降，物体脱离约束但丝仍在，可再次绷紧 | 无（但放久了物体会坠地） |
| **断丝** | 丝线断裂，物体完全自由飞出；断丝瞬间附加一次"抖腕"冲量 | 该丝进入 1.5 秒重凝 |

**断丝 = 攻击。** 它的代价不是数值资源，而是**1.5 秒内你少一根丝**。这就是全部的资源管理，不需要任何资源条 UI。

### 2.4 数值常数

| 常数 | 值 | 说明 |
|---|---|---|
| 重力 g | 20 m/s² | 比真实大，2D 手感更好 |
| 主角质量 m_p | 0.5 | 全场最轻的可动单位之一 |
| 收丝速度 v_reel | 8 m/s | 基础值；"疾丝"心法提升至 14 |
| 丝线基础长度 | 6 m | 最长 12 m |
| 张力上限 T_max | 400 | 超限进入濒断；"韧丝"心法提升至 700 |
| 断丝重凝 | 1.5 s | 固定值，不随进度变化 |
| 物理步长 | 1/60 s 固定 | 确定性要求 |

**张力反馈（机制与表现合一）：**
- T < 60% → 丝线为暗金色，静止
- 60% ≤ T < 85% → 丝线转亮金，开始轻微正弦波动
- 85% ≤ T < 95% → 丝线剧烈抖动，发出颤音（古琴单弦，音高随 T 上升）
- T ≥ 95% → 丝线泛白，颤音变为连续的、不和谐的高频
- **达到上限 → 丝线"拉紧"为刚性约束**：不再伸长，轻的一端被拉向重的一端；两端都动不了时，主角无法继续往张力增大的方向移动

> **v1.2 修订（2026-09，创始人提案，见 DECISIONS D-032）**：原文为「超限 → **断弦**，一声清脆的"啪"，主角反噬硬直 0.8 秒」，现已取消。
> 原因是创始人首轮实机试玩反馈「**丝线什么时候会断太难掌握了**」——不可预测的危险会破坏"读懂物理"这一核心体验。
> 改为"拉紧"之后，张力从一件**危险**变成一条**可预测的能力边界**，且实测甩速更高（12.3–22.6 m/s）。
> 代价是**失去了"丝线会被用坏"这个风险机制**，R2 若要补回需另设机制。张力四档的**比例**（60/85/95%）不变。

玩家不看 UI，只听音高与丝线的粗细明暗，就知道自己离"拉紧"还有多远。

### 2.5 伤害公式

伤害分三种类型，对应三种物理量：

```
冲击伤害（对厚重目标）
  D_impact = (m_eff × v_rel) / 4
  要求 m_eff ≥ 3，否则目标纹丝不动、无伤害

切割伤害（对高速轻薄目标）
  D_cut = (v_rel²) / 60
  要求 v_rel ≥ 15，否则被弹开

撕裂（处决，仅对可缠绕目标）
  条件：同一目标被两条丝从相反方向拉，张力差 > 300
  效果：无视血量直接击杀
```

其中 `m_eff = min(m_攻击物, m_目标)`。

**设计意图：** 两个公式的物理量不同——一个是动量 `mv`，一个是动能 `v²`。这保证了**没有一种物体会通吃全场**：石块打不了墨刃（速度不够），陶罐打不了墨甲（质量不够）。玩家必须**换弹药**，而不是换数值。这就是"没有标准答案"在数学上的实现。

### 2.6 质量表

以「墨卒」质量为 1 单位。

| 物体 | 质量 | 用途 |
|---|---|---|
| 主角 | 0.5 | — |
| 墨刃 | 0.5 | 敌方 |
| 陶罐 / 竹叶 / 念珠 | 0.6 | 高速弹丸 |
| 墨卒 | 1 | 敌方 |
| 竹 | 2 | 弹性体，可弯不可移 |
| 铁链 / 墨缚 | 3 | 可甩，可缠绕 |
| 石块 | 4 | **万用弹丸** |
| 墨甲 | 20 | 敌方 |
| 钟 / 鼓 | 25 | 重物 + 弹性 |
| 梁柱 / 佛像部件 | 40–60 | 超重，主要作为锚点与移动手段 |

## 3. 操作设计

### 3.1 触屏（微信小游戏 / 手机）

**两根手指，四个动词。** 左手拇指负责移动，右手负责丝线。

| 手势 | 作用 |
|---|---|
| 左半屏拖拽 | 移动 |
| 右半屏从主角向外拖拽 | **牵**：拖向目标松手即连接；拖向空处取消 |
| 右半屏按住不放 | **收**：缩短所有丝线 |
| 右半屏向外推 / 下滑 | **放**：增加丝线长度 |
| **点击画面上已有的丝线** | **断**：切断该丝。丝线本身就是按钮 |

**关键决策：丝线即 UI。** 不设独立的"断开"按键。金线是游戏里唯一高饱和的元素，让它同时承担操作入口——点击它就是断它。这既解决了触屏按键数量问题，也让"金线"从美术装饰升级为交互核心。

### 3.2 键鼠（PC）

| 操作 | 按键 |
|---|---|
| 移动 | WASD / 方向键 |
| 瞄准 | 鼠标 |
| 牵 | 左键（按住拖向目标，松手连接） |
| 收 / 放 | 滚轮上下，或 空格 收 / Shift 放 |
| 断 | **点击已连接的丝线**，或 Q 断最近的一根 |

### 3.3 为什么上限是 1→2→3→4 而不是一开始就 4

4 根丝在触屏上超出人类的工作记忆负荷（能同时追踪的动态目标约 3 个）。所以：

- **序章**：1 根。只能做一件事——甩东西。
- **第一章末**：2 根。可以"一主一辅"，学会了双丝反拉和摆荡。
- **第三章**：3 根。人型弹弓成立（2 锚点 + 1 弹丸）。
- **终章**：4 根。天罗。

**丝线数量就是难度曲线，也就是进度条。** 玩家不需要看任何数值成长。

## 4. 战斗系统

### 4.1 敌人：弱点即物理分类

这是本设计最重要的一张表。**敌人不是用数值区分的，是用物理量区分的。**

| 名称 | 形态可读性 | 质量 | 弱点物理量 | 有效手段 | 无效手段 |
|---|---|---|---|---|---|
| **墨卒** | 松散的墨点，缓慢蠕动 | 1 | 任意 | 什么都行 | — |
| **墨甲** | 六边形硬壳块，行动迟缓，撞击地面有闷响 | 20 | 动量 `mv` | 重物投掷、连锁撞击、坠落 | 轻物高速撞击（直接被弹开） |
| **墨刃** | 极薄的墨片，高速游走，带拖尾 | 0.5 | 速度 `v²` | 弹弓、角动量加速、高速弹丸 | 重物慢速撞击（打不中） |
| **墨缚** | 藤蔓状，主动伸出触须缠绕丝线 | 3 | 反向力差 | 双丝反向拉 → 撕裂 | 单方向撞击 |
| **墨巢** | 固定在地形上，持续生成墨卒 | 静止 | 结构承重点 | 击中承重点使其崩塌 | 正面撞击 |

**可读性规则：** 敌人在**攻击前 0.5 秒**会改变形态预示它的类型——
- 墨甲会先"凝固"变暗
- 墨刃会先"拉长"并加速
- 墨缚会先"张开"触须

玩家看到形态变化就知道该切什么弹药。**这是"可学习的深度"，不是"需要背攻略的深度"。**

### 4.2 核心技术清单

按教学顺序排列。**前四项是设计好的，后四项是留给玩家自己发现的。**

**设计好的：**

1. **投石**（1 丝）
   连接石块 → 甩动 → 断。适用于墨甲。
   *物理原理：角动量守恒。*

2. **摆荡**（1 丝，离地状态）
   连接上方的梁柱/钟 → 收丝 → 自己飞过去。
   *物理原理：质心运动。这是位移，也是逃命手段。*

3. **流星**（2 丝）
   一根连石块，一根连上方锚点 → 像钟摆一样荡起来 → 在最低点收丝加速 → 断。
   *物理原理：`v ∝ 1/r`，半径越小越快。*

4. **人型弹弓**（3 丝）
   两根丝分别连接左右两根柱子作"弓架"，第三根连弹丸作"弓弦"。玩家向后退，身体充当第三锚点把弹丸拉到位，然后断弓弦。
   拉距越长，初速越高（弹性势能）。
   *物理原理：胡克定律 + 抛物线。*

**留给玩家的（涌现空间）：**

5. **双截棍** — 用丝把两个敌人连起来，甩动其中一个，另一个被带动。
6. **接物回掷** — 连住敌人射来的箭/石，顺着来势收丝卸力（不抵抗 → 不受伤），然后反向甩回。这是"借力打力"的入门形态。
7. **锚定锁** — 把 BOSS 的武器丝连到柱子上。它挥不动，露出破绽。
8. **天罗** — 4 根丝同时连接 4 个物体，一次断丝同时命中 4 个目标。

### 4.3 借力打力（终章核心）

这是全游戏最高阶的技术，也是主题的最终表达。

**规则：** 当敌人以速度 `V` 挥动武器（或投出物体）时，玩家用丝连接该武器的**运动方向前方**，然后收丝。因为丝只能拉，玩家会获得：

```
玩家最终速度 = 武器速度 V + 收丝速度 v_reel（矢量叠加）
```

**玩家没有产生任何力量，只是搭上了敌人的力量。** 这就是四两拨千斤在物理上的确切含义。

**输入难点与解法：** 对准一把正在挥动的巨剑在触屏上几乎不可能。所以引入**「凝神」**——按住收丝键的同时，世界时间流速降至 15%，玩家的操作速度不变。凝神有 3 秒上限，用完后需要 8 秒恢复。

凝神不是"子弹时间外挂"，它是**这个操作在触屏上存在的必要条件**。同时它也让"借力打力"有了仪式感。

### 4.4 涌现翻译层（慢镜与命名）

**这是把"深度"转化为"体验"的关键系统。**

物理沙盒的深度是涌现的，而涌现是不可见的。玩家做了一个精彩操作，他以为那是运气。所以游戏必须主动告诉玩家：**你刚才做的事情很了不起，它叫这个名字。**

触发条件与命名：

| 命名 | 触发条件 |
|---|---|
| **一石** | 单次投石击杀 |
| **连环** | 链式撞击连续命中 ≥ 2 次 |
| **弹弓** | 拉距 > 5m 后命中 |
| **借刀** | 用敌人自己的武器或投掷物击杀敌人 |
| **四两** | 用质量小于目标 1/10 的物体击杀 |
| **一线** | 单场战斗仅用 1 根丝完成 |
| **无丝** | 单场战斗全程未使用丝线（纯环境击杀） |
| **天罗** | 一次断丝同时命中 4 个目标 |

**表现：** 命中瞬间 0.3 秒慢镜 + 墨色晕染扩散 + 命名以毛笔字横向扫入 + 古琴一记重按。

**"一线"和"无丝"是最重要的两个。** 它们是设计师没有设计的解法，是玩家自己发明的。这两个成就的存在，本身就在向玩家宣告："这个游戏允许你绕过我。"——这比任何宣传语都更能传达"物理引擎本身就是设计师"。

### 4.5 预判线（可读性的技术保障）

**牵住物体时，从物体沿当前速度方向显示一条虚线轨迹，长度约 0.3 秒。**

- 不显示碰撞后的反弹
- 不显示碰撞后其它物体的运动
- 同时显示**该物体的伤害类型和预估值**（如"冲击 14"或"切割 3（不足）"）

**为什么必须有：** 没有它，物理就是混沌，玩家无法规划，也就无所谓"精通"。有了它，物理变成可推理的——玩家能验证自己对 `mv` 和 `v²` 的理解是否正确。

**为什么只显示 0.3 秒：** 保留了弹射和连锁的预测难度。玩家能瞄准，但不能完全预知结果。技巧空间由此保留。

**可选：** 新手默认开启；通关一次后默认关闭（显示为荣誉标记）；高难度模式强制关闭。

## 5. 成长系统：心法

**玩家永远不会变强。玩家只会多一种动词。**

没有等级、没有属性、没有装备数值。全部成长是**新的丝线性质**。

| 心法 | 获得 | 效果 | 打开的技术空间 |
|---|---|---|---|
| **素丝** | 初始 | 基础丝线 | 投石 |
| **韧丝** | 序章末 | 张力上限 400 → 700 | 更长的蓄力窗口；可以拉动更重的物体 |
| **疾丝** | 第一章末 | 收丝速度 8 → 14 | 流星、快速加速 |
| **双生丝** | 第二章中 | 第二根丝 | 双丝反拉、初阶弹弓 |
| **回丝** | 第三章中 | 断丝后 0.5 秒内可"召回"并重置物体速度 | **连锁撞击的时机修正**——这是连锁技术成立的前提 |
| **三才丝** | 第三章末 | 第三根丝 | 人型弹弓完全体 |
| **墨丝** | 第四章中 | 可以附着于「无相」本体 | 甩动敌人打敌人（双截棍） |
| **万象丝** | 终章 | 第四根丝 | 天罗 |

**注意"回丝"的设计。** 连锁撞击需要精确的时机，而触屏玩家做不到精确时机。回丝给了 0.5 秒的容错窗口——**用机制补偿输入精度，而不是降低难度**。

## 6. 关卡设计

### 6.1 结构原则

**每一章的"环境主题"就是"物理主题"的隐喻。** 这不是文学修辞，这是让玩家"感觉到"物理规律的方式。

**每个关卡必须满足：**
1. 引出 **1 种环境物体** × **1 种物理原理**
2. 有 **≥ 3 条通向胜利的物理路径**
3. 设一道**「门」**——只有理解了本关原理才能通过的进度锁

**「门」是唯一的教学手段。** 没有文字教程。门是这样的东西：一扇重达 60 的木门，旁边只有一根悬吊的钟。玩家必须想到"把钟荡起来砸门"。想到了，就学会了摆荡。

### 6.2 六章

#### 序章·荒村（5 关）
- **物理主题**：拉力与质量差
- **环境物体**：石块、陶罐、木栅、水井辘轳、晒谷架
- **敌人**：墨卒
- **教学**：牵 / 收 / 断；轻物打人、重物拉人
- **丝线**：1 → 2
- **关底**：墨巢。需要在井口用辘轳吊起的重物砸穿它
- **情绪目标**：让玩家在第 5 分钟自己想到"我可以用石头砸它"——那一刻他"懂了"这个游戏

#### 第一章·断桥（5 关）
- **物理主题**：角动量守恒
- **环境物体**：断裂的梁柱（可甩）、悬吊铁链（可荡）、松动的桥板、水流（推动物体）
- **敌人**：墨甲
- **教学**：收丝加速（半径变小、速度变大）；钟摆
- **丝线**：2
- **BOSS·桥守**：巨型墨甲，在断桥两端来回冲撞。它只在冲到**最远端**时甲壳张开露出核心。玩家必须用桥板做弹丸，并在它折返的瞬间断丝
- **关底技巧**：这道 BOSS 逼玩家理解"时机比力量重要"

#### 第二章·古寺（5 关）
- **物理主题**：弹性势能与抛物线
- **环境物体**：钟、鼓（弹性体，撞击后回弹）、佛像部件（超重，只能当锚点）、立柱、悬幡（可缠绕）
- **敌人**：墨刃
- **教学**：人型弹弓；预判抛物线与反弹
- **丝线**：2 → 3
- **BOSS·无面僧**：悬浮在空中，持续抛出念珠。念珠可被丝连接并甩回（接物回掷的正式教学）
- **关底技巧**：玩家必须学会"用敌人的东西打敌人"

#### 第三章·竹林（5 关）
- **物理主题**：动量守恒与链式传递
- **环境物体**：竹（弹性体，可弯、可断、断裂后成为长矛）、竹叶（极轻的微型弹射物）、溪石
- **敌人**：墨缚、墨巢
- **教学**：连锁撞击；双丝撕裂
- **丝线**：3
- **BOSS·竹影**：大量墨卒列队推进，本体在队列最末端。必须链式清理。**链式每传递一层，伤害乘 1.3**（这是游戏对物理的主动"作弊"，目的是让连锁撞击有明确回报）
- **关底技巧**：这道 BOSS 让"连锁撞击"从技巧变成必答题

#### 第四章·浮屠（5 关）
- **物理主题**：参考系与相对速度
- **环境物体**：悬空塔（多层，每层的重力方向不同）、坠石、经轮（可旋转）
- **敌人**：墨甲 + 墨刃混合编队
- **教学**：借力打力（用敌人的速度）；坠石反弹
- **丝线**：3 → 4
- **BOSS·塔灵**：在天花板与地板之间切换重力方向。玩家必须把自己的坠落速度当成武器——**在重力翻转的瞬间断丝，物体以两倍相对速度飞出**
- **关底技巧**：这道 BOSS 让玩家理解"速度是相对的"

#### 终章·墨渊（3 关）
- **物理主题**：综合
- **环境物体**：凝固块（BOSS 身上唯一的实体锚点）、墨池、深渊
- **敌人**：无相本体
- **教学**：无。全部技术自由组合
- **丝线**：4
- **BOSS·墨渊之主（三阶段）**：
  - **阶段一·挥**：BOSS 用巨型墨刃劈砍。玩家连接墨刃，顺方向收丝 → 被甩出去 → 撞向它身上的凝固块
  - **阶段二·守**：BOSS 收回武器护住核心。玩家必须用**两根丝**同时连接墨刃的两端，把它反拉向它自己
  - **阶段三·沉**：BOSS 化为墨池，凝固块沉入其中。玩家必须把所有凝固块用丝拽出并砸向同一个点
- **主题表达**：整个游戏你从未主动产生过力量。你只是重新分配了它。

## 7. 序章前 12 分钟（完整实作）

这一节是整个设计的样板。**如果这 12 分钟做对了，游戏就成立了。**

### 0:00–1:00 牵
空场景。一块石头。屏幕上只有一行提示：**「按住，拖向石头」**。
连上后丝线绷紧，石头微微晃动。提示消失。**没有别的。**

### 1:00–2:00 收
提示：**「按住不放」**。
石头被拉向主角（因为主角踩在地上，等效质量无限）。石头悬在半空，开始摆动。

### 2:00–3:00 断
提示：**「点一下丝线」**。
石头飞出，砸碎一个陶罐。**不教"这可以用来打架"，只教"这会让东西飞"。**

### 3:00–5:00 第一个墨卒 ★
一个墨卒从右侧缓慢爬来。左边有一块石头。**没有任何提示。**

这是整个游戏最重要的一分钟。玩家必须自己把前三个动作串起来。如果他做到了，他就"懂了"这个游戏——**不是懂了操作，是懂了"这个游戏允许我自己想"。**

如果 60 秒内没有动作，石头会微微发光（极其克制的提示）。不弹文字。

### 5:00–8:00 质量差
场景给出一个 **60 质量的梁柱** 和一个 **0.6 质量的陶罐**。
玩家连梁柱 → 收丝 → **自己被拉了过去**。

第一次展示"质量差决定谁是主动方"。玩家学到：
- 轻的东西用来打
- 重的东西用来移动

**这一幕不需要任何文字。** 物理自己会说话。

### 8:00–12:00 双丝
解锁第二根丝。场景：一个墨卒 + 一根悬吊的横梁 + 一道深沟。
玩家可以：
- 连横梁荡过深沟（位移）
- 连墨卒甩出去（攻击）
- 用两根丝把墨卒和横梁连起来（双截棍雏形）

**这是全游戏第一次出现"一个问题多个解法"。** 玩家在这里第一次体会到"没有标准答案"。

## 8. 表现层

### 8.1 美术：水墨的技术实现

水墨风格对 2D 物理游戏是**技术上最友好**的美术风格，因为大量留白意味着大量透明像素和极少纹理。但"墨的流体感"需要专门处理。

**场景**
- 手绘水墨素材，背景为透明，靠留白构成画面
- 远山：3–4 层视差 + 极低对比度（5%–15% 不透明度）
- 单屏房间制，相机正交投影，整数像素对齐防抖动

**无相（墨体）的渲染** —— 这是唯一的技术难点
```
1. 把每个墨体单位的粒子画到 1/4 分辨率的 RT 上
2. 两次高斯模糊（可分离）
3. step(u, 0.5) 得到清晰但连通的墨形边缘
4. 把溅射墨点也画进同一张 RT → 墨点和墨体自然融合
```
这是 **metaball 的廉价近似**，在移动端完全可行（模糊在半分辨率上做，成本极低），且视觉上比精确 SDF 更"水墨"——因为墨本来就有晕染。

**灵丝**
- 用 **Verlet 绳索**（非刚体）模拟，8–12 段
- 唯一的高饱和元素：加色混合 + 轻微 bloom
- 张力用**线宽**表达：越紧越细越亮
- 颜色随张力变化（见 2.4）

**色彩铁律：画面中除金线外，所有元素饱和度不超过 15%。** 金线必须是唯一焦点。这条铁律要写进美术规范，任何宣传图、UI、特效都不得违反。

### 8.2 音效：把机制变成声音

**古琴单弦是核心音色，而且它直接承载机制信息。**

| 事件 | 声音 |
|---|---|
| 丝线连接 | 一记清亮的「铮」 |
| 收丝 | 持续音，**音高随张力线性上升** |
| 张力 > 85% | 加入**濒断颤音**（不和谐的高频颤动） |
| 张力 > 95% | 颤音变为连续、刺耳 |
| 断丝 | 一记清脆的「啪」（断弦） |
| 超限断弦 | 「啪」+ 主角闷哼 |
| 物体命中墨体 | 低沉的水声「噗」 |
| 物体命中硬物 | 木质/石质的实体撞击声 |
| 高价值事件 | 古琴一记重按（配合慢镜） |

**环境音只有：风声、水声、墨物流动的低沉嗡鸣。**
**BGM 极简。只有 BOSS 战有完整旋律。** 这条保留原设计，它是对的。

**关键原则：玩家闭着眼睛也能听出丝线的张力状态。** 这让操作不需要看 UI，在触屏上尤其重要（手指挡视野）。

### 8.3 相机

2D 物理战斗的最大表现难题：**你没法同时看见"甩动的东西"和"要打的目标"。**

解法——**三段式相机**：

1. **蓄力时**：相机以主角为中心，随张力略微拉远（张力越高视野越广）
2. **断丝瞬间**：**0.15 秒定格**（不是慢镜，是完全静止）+ 屏幕轻微缩放脉冲
3. **飞行时**：相机跟随飞出的物体，加速度线/残影；主角留在画面边缘

**第 2 步的"定格"是最重要的手感设计。** 它把"释放"这个动作从"松手"变成一个**有仪式感的瞬间**。这是《牵丝》的操作爽感来源。

### 8.4 UI

**极简，几乎不存在。**

- 只有丝线数量指示（4 个小圆点，未使用的为暗金）
- 凝神有细圆环计时
- **没有血条。** 主角受伤用画面表现：墨色向画面边缘侵蚀。侵蚀到边缘 = 死亡
- **没有伤害数字。** 用墨色晕染的扩散范围表示伤害大小
- 预判线只在牵住物体时出现

**唯一允许的文字是「命名」（见 4.4）。** 除此之外全游戏不超过 500 字文本。

## 9. 技术方案

| 项 | 选择 | 理由 |
|---|---|---|
| 引擎 | Cocos Creator 3.x 或自研 | 微信小游戏原生支持；Unity WebGL 在移动端小游戏上体积和性能都吃亏 |
| 物理 | **Box2D + 自研 Verlet 绳索** | Box2D 成熟稳定；绳索用 Verlet 比刚体链便宜且不抖 |
| 确定性 | 固定 1/60 步长，禁用所有随机数 | 速通 / 挑战 / 录像的前提 |
| 渲染 | 半分辨率 RT 做墨体模糊 | 移动端可行 |
| 包体 | 主包 < 4MB，水墨素材分包按章加载 | 水墨素材本身极小（大量透明），这是该美术风格的额外红利 |
| 目标机型 | 中端安卓（骁龙 6 系）稳定 60fps | 微信小游戏的用户主力机型 |

**性能预算（单屏）**：
- 刚体：≤ 40 个
- Verlet 绳索：≤ 4 根 × 12 段
- 墨体粒子：≤ 800
- Draw call：≤ 60

**为什么这个预算够用：** 单屏房间制 + 大量留白 + 敌人数量少（墨甲这种重单位一屏最多 3 个）。**水墨美术风格在这里不是妥协，是性能优势。**

## 9.5 维度决策：为什么是 2D 玩法 + 2.5D 表现

### 结论

**玩法严格锁定在 2D 物理平面，渲染与相机走 2.5D。这个决定不可动摇。**

### 核心理由：3D 增加的是操作复杂度，不是机制深度

这个游戏的全部深度来自**标量物理量**——动量 `mv`、动能 `v²`、张力差。这些概念在 2D 里是完整的、可读的、可推理的。

加一个 Z 轴不会让「动量 vs 动能」这个克制关系变深一分。它只会让玩家多一个轴要瞄准。**这是最差的一种交换：三倍成本，买一堆操作负担，不买任何深度。**

### 四条致命的具体问题

**① 预判线在 3D 里会失效。**
预判线是整个游戏可学习性的物理载体。2D 里它是一条平面曲线，一眼读懂。3D 里它必须是空间曲线，玩家要判断深度——所有 3D 弹道游戏最后都只能靠**落点标记**解决。而一旦玩家开始读标记而不是读轨迹，**「读懂物理」这件事就消失了**，游戏退化成「对准那个圈」。

**② 角动量守恒在 2D 是标量，在 3D 是矢量。**
第一章教的是「收丝 → 半径变小 → 速度变大」。2D 里玩家**看得见**半径在缩小。3D 里石头在一个平面上绕你转，相机稍偏，这个平面就侧对镜头，加速过程**完全不可见**。核心教学直接崩塌。

**③ 操作带宽不够。**
两根手指管 4 根丝。3D 瞄准需要三个自由度，触屏摇杆做不到。三条路都是死路：砍丝线（玩法深度砍半）、强制鼠标（微信小游戏计划作废）、自动锁敌（瞄准是这个游戏唯一的主动动词，锁敌等于把它删了）。

**④ 水墨本身就是 2D 的媒介。**
留白、平面化空间、散点透视——水墨画的语言建立在「不画深度」上。3D 化之后得到的不是水墨，是**卡通渲染**。

### 2.5D 的具体做法

物理平面绝不动摇，只让**渲染和相机**拥有三维自由度：

| 项 | 做法 |
|---|---|
| 物理 | Box2D，严格锁定 XY 平面 |
| 相机 | **正交投影**，但有：轻微旋转（±8°）、Dolly 推拉、滚动 |
| 视差 | 6–8 层水墨层（远山 / 雾 / 中景 / 玩法层 / 前景） |
| 景深 | 前景墨层虚化，把玩法平面夹在中间 |
| 断丝瞬间 | 相机倾斜 8° + 缩放脉冲，制造「甩出去」的动量感 |
| 蓄力时 | Dolly 拉远，张力越高视野越广 |

**收益最大的是视差层。** 成本极低（Cocos Creator 3.x 原生支持），但它是 2D 和「一幅有纵深的水墨画卷」之间的全部差别。

另外还有一样纯 2D 做不到、2.5D 能救的东西：**丝线缠绕**。2D 里没法表现丝绕柱子一圈；2.5D 里可以用带缩放的螺旋线伪造。

### 什么情况下我会改口

如果这个游戏的核心是**位移**而不是**击打**——即在城市里荡来荡去——那就该做 3D，因为空间本身就是内容。

但《牵丝》的核心是「读懂物理然后一击」，这是**平面行为**。所以它该像一幅**卷轴**，而不是一个盒子。卷轴可以有远近，但它始终是平的。

## 10. 平台与商业化

### 10.1 推荐路径：三段式

**阶段一：微信小游戏 · 免费验证版（3–5 关，约 4 个月）**
- 免费，**无广告、无内购**
- 个人主体可免版号（需软著 + 备案 + 自审自查报告）
- 内容：序章 + 第一章的前 2 关，加上「墨渊试炼」挑战模式
- **目的不是赚钱，是验证核心手感与传播力。** 物理沙盒游戏的手感只能靠真人测试验证，纸面推演无效
- 关键指标：**第 5 分钟的墨卒遭遇战，有多少玩家自己想到了用石头？** 这个数字决定了整个游戏是否成立

**阶段二：挑战模式扩展（+2 个月）**
- 若阶段一数据成立，把「墨渊试炼」做深：同一关，用更少的丝、更短的时间、更离谱的方式通关
- **这是微信小游戏真正的留存引擎**，因为它是可重复游玩的、有排行榜的、有社交比较的
- 你原设计里的「挑战模式」「速通模式」不应该是通关后的解锁内容，**它们应该是主玩法**

**阶段三：完整买断版（12–18 个月）**
- **PC（Steam）为主平台**，TapTap / App Store 移动端买断
- 完整 6 章，8–12 小时
- 微信小游戏版同步更新付费章节（此时需企业主体 + 版号）

### 10.2 为什么不是"微信小游戏独占"

2025 年小游戏市场 535 亿元，内购已占 68%，**IAP 领先品类是 MMO / SLG / RPG**——都是长线运营、强社交、有付费深度的品类（[中国经营报](https://finance.sina.cn/2026-01-24/detail-inhiiuck1635591.d.html)）。

一个 8–12 小时线性单机游戏在小游戏生态里的结构性劣势是：**没有长线付费点、没有社交裂变、发现机制极度依赖买量。**

但微信小游戏的**挑战模式**恰好能补上这个洞：物理沙盒的"同一关不同解法"天然是排行榜素材，而且**物理意外极易传播**（"你看我这个操作"）。所以路径应该是**用挑战模式做小游戏，用主线做买断版**。

### 10.3 合规提醒

- 企业主体无论是否商业化均需版号；含内购或广告变现需版号
- 常规审核 3–6 个月，补正可延长至一年以上
- 2026 年 iOS IAP 已打通，微信抽成 15%，首发新游激励上限 400 万（[GameLook](http://www.gamelook.com.cn/2026/01/586148/)）
- 上述为第三方机构与媒体总结，最终以国家新闻出版署与微信官方为准

## 11. 开发计划与风险

### 11.1 里程碑

| 阶段 | 时间 | 交付物 | 验证目标 |
|---|---|---|---|
| **M0 物理原型** | 3 周 | 一个灰盒房间：石块 + 墨甲 + 投石 | 三键操作是否成立？甩动是否有爽感？ |
| **M1 垂直切片** | 3 个月 | 序章前 12 分钟（第 7 节全部内容） | **玩家是否会自己想到用石头？** |
| **M2 小游戏验证版** | 4 个月 | 3–5 关 + 挑战模式 | 留存、分享率、第 5 分钟的行为数据 |
| **M3 完整版** | 12–18 个月 | 6 章买断版 | 商业表现 |

**M0 和 M1 之间不要做任何美术。** 全灰盒。物理手感不成立的话，水墨再美也没用。

### 11.2 三大风险与对策

**风险一：物理手感做得不好（最高风险）**
"真实物理"和"好玩"之间有鸿沟。对策：不追求真实，追求**可预测**。固定步长 + 轻微动量增益 + 预判线。**必须在 M0 阶段用真人测试验证，不能靠推演。**

**风险二：玩家想不出解法（次高风险）**
没有攻击键 = 没有兜底 = 卡关即死锁。对策：
- 每个遭遇战至少有 3 条通路，其中一条必须**极其明显**
- 60 秒无动作时给极其克制的提示（物体发光，不弹文字）
- 主角可以随时用丝位移逃命，容错来自移动而非攻击

**风险三：涌现不被感知（最容易被忽视）**
玩家做出了精彩操作却以为是运气。对策：4.4 节的命名系统**不是锦上添花，是必需品**。

### 11.3 一句话验收标准

**M1 结束时，找一个没看过设计文档的人玩 12 分钟。**

如果他在这 12 分钟里**主动说出"我能不能把那个东西连到这个上面"**——游戏成立。

如果他从头到尾在等教程告诉他怎么做——不成立，回去改。

## 附录 A：伤害数值速查

```
冲击伤害 D_impact = min(m_att, m_tgt) × v_rel / 4      [要求 m_eff ≥ 3]
切割伤害 D_cut    = v_rel² / 60                          [要求 v_rel ≥ 15]
撕裂              = 直接击杀                             [要求反向张力差 > 300]

参考：石块(4) @ 20m/s → 冲击 20
      钟(25)   @ 8m/s  → 冲击 50
      陶罐(0.6)@ 40m/s → 切割 26.7
      石块(4) @ 25m/s → 切割 10.4
```
